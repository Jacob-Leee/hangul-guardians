# 열두동물 한글 수비대 — 인수인계 문서

작성: 2026-10-30 · 기준 버전: v29.4 (Claude 아티팩트 버전과 내용 동일, 파일만 나눔) · 앱 주소: https://jacob-leee.github.io/hangul-guardians/ (GitHub `Jacob-Leee/hangul-guardians`, main 브랜치 루트를 GitHub Pages로 배포)

## 1. 한 줄 요약

5세 아이의 **한글 읽기 유창성**을 위한 웹 게임. 고양이 악당이 망가뜨린 동화책 속에 들어가, **책 속 기록을 읽고** 틀린 문장을 고쳐 이야기를 되찾는다. 지금은 1권 〈토끼와 거북이〉만 완성, 나머지 11권은 엔진만 준비됨.

- 사용자: 만든 사람(보호자)과 5살 아이. 아이는 받침 있는 글도 꽤 잘 읽는다(2026-10 보호자 확인). 목표는 유창성과 **이해**. 그래서 기본은 아이가 직접 읽고, 소리는 필요할 때만(읽기 도움 3단계).
- 단계: 프로토타입. 설치형 웹 앱(PWA)으로 아이패드·아이폰 홈 화면에서 오프라인 실행(v29, 아이폰 화면 맞춤은 v29.4). 로그인·결제·앱스토어 출시는 아직 시작 안 함.
- 기술: 순수 HTML/CSS/JavaScript. 빌드 도구·프레임워크·서버 없음.

## 1-1. 작업 분담: 그림은 ChatGPT, 프로그램은 Claude (2026-10-30부터)

- 보호자가 GitHub로 ChatGPT와 Claude를 함께 연결했습니다. **ChatGPT는 그림만** 만들어 `incoming/`에 올리고(커밋 메시지 `img: …`), **Claude가 프로그램**(코드·연결·테스트·배포)을 맡습니다. ChatGPT에 줄 첫 메시지는 `docs/CHATGPT_START.md`, 지금 필요한 그림과 프롬프트는 `docs/IMAGE_REQUESTS.md`.
- **Claude가 프로그램을 올리기 전에 매번 할 일 (순서 중요)**
  1. `git fetch` 후 main의 새 커밋, 다른 브랜치, 열린 PR을 확인합니다(`gh api repos/Jacob-Leee/hangul-guardians/pulls?state=open`). GraphQL(`gh pr list`)은 막혀 있으니 REST만 씁니다.
  2. 새 커밋이 있으면 먼저 받아서(`git merge --ff-only origin/main`) 바뀐 파일을 봅니다. `incoming/`의 그림은 WebP로 줄여 제자리에 넣고 코드에 연결합니다. 처리한 원본만 `incoming/`에서 지웁니다.
  3. 그다음 프로그램을 고치고 테스트한 뒤 올립니다. 저장소를 새로 채울 때 `incoming/`과 처리하지 않은 남의 파일을 지우지 않습니다(마지막으로 Claude가 아닌 사람이 올린 파일이 사라지면 멈추고 확인).
- 그림이 대화로 오면(보호자가 직접 첨부) 같은 방법으로 넣고, 원본은 올리지 않습니다.

## 2. 실행 방법

- **실제 사용:** GitHub Pages 주소를 아이패드 Safari로 열고 공유 → 홈 화면에 추가 (README 참고). 처음 한 번 열면 모든 파일(약 22MB)이 기기에 저장되어 인터넷 없이 실행됩니다.
- **개발:** 폴더에서 `python -m http.server` → http://localhost:8000. `index.html`을 파일로 바로 열어도 되지만 배경음악·오프라인 기능은 http에서만 동작합니다.
- **배포:** 파일을 고친 뒤 `python tools/make_app.py` → `main`에 푸시 → 1~2분 뒤 반영. (4-6 참고)
- 글꼴(Jua, Gowun Dodum, Fredoka)은 v29부터 모두 `assets/fonts/`에 들어 있습니다(Google Fonts 요청 없음, OFL 라이선스 파일 포함).
- 저장은 브라우저 `localStorage`: 게임 진행 `hiq2`, 직접 넣은 캐릭터 그림 `hiq2img`. **홈 화면 앱과 Safari 탭은 저장소가 따로**이고 다른 기기로도 옮겨지지 않습니다 → 설정 → 진행 백업(백업 코드)으로 옮깁니다.

## 4-1. 한글 놀이터 (미니게임 시스템)

모든 미니게임이 **같은 규칙**을 씁니다. 게임마다 다른 것은 "화면에서 무엇을 누르는가"뿐입니다.

| 공통 규칙 | 내용 |
|---|---|
| 단계 | 게임마다 5단계 (`LADDER`). 1 글자 소리(`syl1`) → 2 더 많은 글자(`syl2`) → 3 내 낱말·그림 보고(`wpic`) → 4 내 낱말·헷갈리는 보기(`wnear`) → 5 내 낱말·소리만 듣고(`wsound`). 짝꿍 카드는 3–4단계 `wpic`, 5단계 `wmix`(다음 레벨 섞기), 기차 5단계는 문장 만들기(`sent`), 빈칸은 `FILL_LV`. **3–5단계의 낱말은 아이의 낱말 레벨(4-2)에 맞춰 매번 새로 고름** |
| 한 판 | 시간 제한 없음. 정해진 개수(보통 6–8개)를 맞히면 끝 |
| 별 | 첫 시도에 맞힌 비율: 90% 이상 ★3, 65% 이상 ★2, 나머지 ★1 (짝꿍 카드는 뒤집은 횟수 기준) |
| 잠금 해제 | 한 단계에서 ★2 이상이면 다음 단계 열림 (`pgOpenLv`) |
| 약한 글자 반복 | 틀린 글자/낱말이 더 자주 나옴 (`G.pgm`, `pgPick`). 맞힌 기록은 글자 실력표(`G.m`)에도 반영 |
| 비슷한 오답 | 글자는 같은 자음·모음, 낱말은 같은 첫 글자·같은 길이로 오답을 만듦 (`pgNear`) |
| 적응 | 연속 2번 틀리면 정답이 반짝이고 느려짐, 연속 3번 맞히면 조금 빨라짐 |
| 화면 흐름 | 설명(영웅 목소리) → 준비·시작 → 플레이 → 결과(별, 연습한 글자 목록, 다음 단계) |
| 저장 | `G.pg[게임].s[단계] = 별` |

| 게임 | 바탕이 된 놀이 | 하는 일 |
|---|---|---|
| 🎣 글자 낚시 `fish` | 낚시 놀이 | 소리를 듣고 그 글자 물고기 잡기 |
| 🔨 두더지 콩콩 `mole` | 두더지 잡기 | 들은 글자를 든 두더지만 누르기 |
| 🃏 짝꿍 카드 `pair` | 카드 짝 맞추기(메모리) | 그림 카드와 낱말 카드 짝 찾기. 낱말은 짝을 맞힌 뒤에만 읽어 줌 |
| 🌧️ 글자 소나기 `rain` | 떨어지는 글자 아케이드 | 맞는 물방울 터뜨리기 (줄을 나눠 겹치지 않음) |
| 🚂 글자 기차 `train` | 블록 조립 | 자음+모음 → 글자, 글자 → 낱말, 어절 → 문장 |
| 🧩 빈칸 채우기 `fill` | 빈칸 퀴즈 | 문장에 맞는 낱말 고르기, 완성 문장 읽어 줌 |

| 게임 | 몰입 연출 (v23) |
|---|---|
| 낚시 | 영웅(전신 그림)이 부두에서 낚싯대를 든다. 맞는 물고기를 누르면 바늘이 날아가 물고 → 낚싯대가 휘고 → 물보라와 함께 끌어올려 → 양동이에 쏙(마리 수 증가). 틀린 물고기는 미끼만 톡 건드리고 도망 |
| 두더지 | 망치가 내려치고 "콩!" + 별 눈. 틀리면 두더지가 혀를 내밀고 "메롱~". 흙 튐, 풀·꽃 |
| 짝꿍 카드 | 뒤집는 소리, 카드마다 살짝 기울기, 틀리면 흔들림, 짝이면 "짝!" 도장 |
| 소나기 | 맞힐수록 무지개가 진해짐, 빗줄기, 터질 때 물보라와 웅덩이 물결 |
| 기차 | 블록을 끼울 때 소리, 기차 도착 칙칙, 출발할 때 기적 소리 + 배경(언덕·구름)이 뒤로 흐름, 굴뚝 증기 |
| 빈칸 | 고른 낱말이 빈칸으로 날아가 박힘, 다음 문제는 책장 넘김, 페이지 번호·책갈피 |

효과음은 파일 없이 WebAudio로 만듭니다: `sfx2(이름)` — splash, reel, cast, bonk, flip, pop, plop, whistle, chug. 목소리가 나오는 중이면 자동으로 작게.

**새 게임 추가 방법**: `PGAMES`에 이름·설명·단계 목록을 넣고, `PGM.<id>=()=>({setup, target, hint})`를 만듭니다(필요하면 `prompt`, `say`, `next`, `acc`, `stop`). 정답이면 `pgRight(요소)`, 오답이면 `pgWrong(요소, 누른 항목)`만 부르면 별·기록·적응·결과 화면은 공통 코드가 처리합니다. 스테이지에서 쓰려면 `pgPlay(id, 단계, {stage:true, goal:N})`.

  - 사건: 의뢰 다음(현장 조사 전) / 증언 다음(영웅 기술 전) / 해결 다음(보고서 전).
  - 1권: 프롤로그 다음 / 문장을 고친 다음 / 마지막 화면 전.
  - 한 미션 = `{a, b, q, ans:[글,이모지], o:[[글,이모지],[글,이모지]]}`. `a`는 1·2단계용 한 문장(20음절 이하), `b`는 3단계용 두 문장(52음절 이하). 정답 낱말이 a와 b 모두에 들어 있어야 합니다.
  - 흐름: 소리 내어 읽기 → "다 읽었어요" → 그림 고르기. 낱말을 누르면 그 낱말만 읽어 주고 '도움'으로 기록합니다.
  - '건너뛰기'가 있고, 건너뛴 수는 부모 요약에 보입니다. 끼우는 곳은 `kzGo`·`kzReport`·`bookEnter`·`goStep`(script 단계)·`bFinish`를 감싼 함수입니다. 설정에서 끌 수 있습니다(`G.rmOff`).
- **오늘의 모험** (`G.today`, v29.2부터 기본 '한 바퀴', 설정 `G.tdLen`이 `"short"`이면 예전 3단계):
  - 게임 한 바퀴(`tdLap`): 🎣 낚시 → 🔨 두더지 → 🌀 모험 코스 → 🃏 짝꿍 → 🌧️ 소나기 → ⚔️ 연습 배틀 → 🚂 기차 → 🧩 빈칸. 이야기 모드(동화책·한글 섬 모험·사건 수사대)는 넣지 않음(보호자 요청). 카드의 '하기 ▶'는 아직 안 한 다음 게임, 아이콘을 누르면 그 게임. 같은 게임을 다시 해도 한 번만 셈(`G.today.lap`).
  - 카드에서 시작한 게임은 끝나면 카드로 돌아옴(`TDR`, `tdBack`): 놀이터 결과의 '놀이터' 버튼이 '☀️ 오늘의 모험'으로 바뀌고 ← 도 카드로, 코스·배틀은 결과 버튼 이름이 바뀌고 `closeRun`·`duClose`를 감싼 함수가 카드를 엶. 배틀 '다시 도전'처럼 곧바로 다시 열리면 카드를 띄우지 않음.
  - 게임 4개를 하면 "절반 왔어요! 물 한 모금 마시고 기지개 쭉" 안내. 모두 끝났으면 카드 대신 축하 화면이 먼저 나옴. 레벨 업 화면이 먼저 떠 있으면 그 화면을 닫은 뒤 카드가 열림(화면 두 개가 겹치지 않게).
  - 셈하는 곳: 놀이터 결과(`pgResult`, 섬 스테이지 판은 제외), 자유 코스 끝(`clearRun`·`failRun`, 스테이지 제외), 연습 배틀 끝(`duWin`·`duLose`, 스테이지 배틀 제외).
  - 짧게 모드의 놀이 1판: 가장 덜 한 게임. 3단계면 낱말 단계부터 시작합니다.
  - 읽기 미션 3개: 1권을 아직 안 끝냈으면 1권, 끝냈으면 다음 사건.
  - 낱말 5개 복습: `rmWords`. 낱말 레벨 단어를 읽고 그림을 고르며, 결과는 `pgRec`로 간격 반복에 들어갑니다.
  - 모두 하면(한 바퀴 10개 / 짧게 3개) 축하 화면이 뜨고, 보상은 하루 한 번만 주며 "오늘은 여기까지" 안내를 합니다. 미션을 꺼 두면 읽기 칸은 '이야기 한 편 끝내기'가 됩니다.
- **하루 기록 `G.days[YYYY-MM-DD]`** (35일 보관):

## 4-6. 설치형 웹 앱 (PWA, v29)

  - 새 버전은 기다렸다가 "업데이트"를 누르거나 앱을 완전히 닫았다 열 때 바뀝니다. 게임 도중에는 바뀌지 않습니다.

## 5. 동화책 엔진 — 데이터 형식

책 한 권 = `books/<id>/book.js` 하나 + 그림 폴더. 엔진 코드는 고치지 않습니다.

- **2권 〈시골 쥐와 도시 쥐〉 (v29.3에 열림)**: `books/b2/`. ChatGPT 그림 8장(무대, 이야기 그림 1·2, 시골 쥐·도시 쥐 기본·놀람, 집고양이)에 맞춰 자리를 다시 잡았습니다. 이 무대는 식당이 사람 크기로 그려져 있고 넓은 화면에서는 무대 아래쪽 약 58%만 보이므로, 쥐는 식탁 위가 아니라 식탁 옆 바닥에 서고(받은 이야기 그림 2와 같음) 크기는 `h:26`, 고양이 `h:30`. 시골 집 문은 가로 14%, 길은 세로 약 75%.
  - `page3.webp`는 **임시 그림**(무대 그림의 시골 쪽을 잘라 시골 쥐를 얹음). 진짜 그림이 오면 파일만 바꾸면 됩니다.
  - 선택 그림(걷기·기쁨·뽐내기·덮치기·표지)은 기본 자세와 이야기 그림 1을 대신 씁니다. 오면 `poses`의 파일 이름만 바꿉니다.
  - 목소리 `VOX.sb_country`·`VOX.sb_city`와 읽기 미션 `RMS.b2`는 `js/app.js`(끝부분)에 있습니다(`books/b2/book.js`보다 늦게 정의되는 것들이라서).
  - 끝까지 자동 진행: `node tests/book-auto.js index.html b2` (휴대폰은 끝에 `phone`).

`app.js`의 `BOOKS` 목록(12권: id, 주인 동물, 제목, 악당, 색)은 이미 채워져 있고, `BOOKDATA[id]`가 있으면 그 책이 열립니다.

### 최상위 필드

| 필드 | 뜻 |
|---|---|
| `dir` | 그림 폴더 (`"books/b1/"`) |
| `cover` | 표지 그림 |
| `bg` | 16:9 배경(왼쪽·오른쪽 장면을 이어 붙인 spread). 좌표는 이 그림 기준 % |
| `actors` | `{id:{n:이름, voice:목소리ID, h:키(배경 높이 %), poses:{포즈:[파일, 크기배율]}}}` |
| `at` | 장소 이름 → `[x%, y%]` (발 위치) |
| `broken` / `endState` | 망가진 상태 / 끝 상태의 배치 `{배우:[장소, 포즈]}` |
| `claim` | 악당 때문에 생긴 거짓 주장 말풍선 `{who, t}` |
| `sentence` | 고칠 문장 `{tokens:[...], bad:틀린 칸 번호, fix:맞는 낱말}` |
| `records` | 그림 속 기록 `{k, ic, place, at:[x,y], t:기록 문장, clue:[강조할 말]}` |
| `prologue` | 망가진 이유를 읽는 페이지들 (아래 "읽기 페이지") |
| `enterLine`, `enter` | 책에 들어갈 때 주인 동물 대사, 들어간 뒤 장면 스크립트 |
| `steps` | 게임 단계 목록 (아래) |
| `restored` | 되찾은 이야기 페이지들 |
| `ending` | 보너스 "내 결말 만들기" `{title, ask, lead, lead2, ask2, start, tpl:"…{A}…{B}…", A:[{t,e,s:스크립트}], B:[…]}` |
| `fin` | 끝 인사 (`{vil}` = 악당 이름) |

### 읽기 페이지 (prologue / restored)
`{text, who?, pov?, scene?, fx?}`
- `text`: 화면에 크게 나오는 글. `"따옴표"` 부분은 `who`의 목소리로, 나머지는 내레이터가 읽음.
- `pov`: 한 장짜리 그림 페이지 `{img 또는 bg, fit:"contain", kb:"in"|"pan"|"out"(천천히 확대/이동), vil:true(악당 등장), mentor:true, team:true, deco:[이모지]}`. `"@lib"` = 시작 포스터를 흐리게 깐 도서관 배경.
- `scene`: 배경 위에서 캐릭터가 움직이는 장면 (아래 스크립트 명령).
- `fx:"confetti"`: 색종이.

### 단계 종류 (`steps[].type`)
| type | 하는 일 | 주요 필드 |
|---|---|---|
| `explore` | 그림 속 반짝이는 기록 찾기 | `ask, hint` (기록은 `records`) |
| `choose` | 누구/무엇인지 고르고 근거 기록 고르기 | `qs:[{ask, opts:[[배우ID, 이름]], a, ev:[근거 기록 k], evAsk, hint, evHint, cl}]`, `after:스크립트` |
| `fix` | 기록과 다른 낱말 찾아 고치기 | `alts:[오답 낱말], ask1, ask2, hint1, hint2, cl` |
| `script` | 고친 결과가 화면에서 바뀜 | `intro, script, next` |
| `order` | 일어난 순서대로 페이지 놓기 | `ask, hint, pages:[{img, t, cl}]` |
| `match` | 카드를 맞는 곳에 놓기 (2권 이후용, 아직 미사용) | `ask, hint, items:[{id,t,ic}], targets:[{id,t,ic}], ans:{item:target}` |
| `story` | 되찾은 이야기 읽기 | `pages:"restored"` |

### 스크립트 명령 (장면 연출)
한 줄 = 작은 동작 하나. 기본은 앞 동작이 끝나야 다음으로, `par:true`면 기다리지 않음.

## 7. 꼭 지킬 규칙 (사용자와 합의된 결정)

**저작권·안전**
- 꾸러기 수비대, LEGO, Marvel 등 기존 캐릭터·로고를 쓰거나 흉내 내지 않기. 지금 캐릭터는 사용자가 AI로 직접 만든 것이고, 그림에 박힌 글자·로고는 쓰지 않기.
- 웹에서 찾은 참고 사진을 이미지 생성 참고로 쓰지 않기.
- 출시 전: 마리오를 닮은 `?` 블록과 깃발(달리기 코스)은 다시 디자인하기.

**아이 경험**
- 틀려도 벌 대신 힌트(약한 공격 + 스승님 단서). 쉬움 모드에서는 지지 않음.
- 내레이터는 문장 사이 0.8–1.2초 쉼. 질문 직후 바로 정답을 말하지 않기. 재촉하지 않기.
- 목소리가 동시에 겹치지 않게 (`hush()`로 정리).
- 2단계 난이도는 자동으로 올리지 않기.
- 아이가 직접 읽는 것이 기본(읽기 도움 3단계). 긴 글을 저절로 읽어 주지 않기. 소리는 아이가 🔊를 누를 때만.
- 읽기 미션의 '건너뛰기'를 없애지 않기. 억지로 막는 대신 부모 요약에 보여 준다.
- 기본 흐름은 '오늘의 모험'. 기본은 '한 바퀴'(약 25–35분, 2026-10-30 보호자 요청), 설정에서 '짧게'(10–15분). 하루 중에 나눠서 해도 되고, 다 하면 쉬라고 안내한다.
- 진행 기록은 기기 밖으로 보내지 않기(로그인·서버를 만들기 전까지).
- 펫(파트너) 기능은 사용자 요청으로 제거함. 다시 넣지 않기.

**정직**
- 실제 음성 파일이 없으면 "음성 구현됨"이라고 말하지 않기.

**작업 분담 (2026-10-30)**

## 10. 수정할 때 주의

- `app.js`는 전역 변수로 이어진 하나의 스크립트입니다. 함수 이름이 겹치지 않게 하세요. CSS 클래스 이름도 겹치면 깨집니다. 예: 그래프용 `.bars`와 영화 띠가 겹쳐 결승 장면이 까맣게 나온 적이 있어서, 영화 띠 클래스를 `cine`로 바꿨습니다. 또 지도 타일 클래스 `.R`(풀밭 배경)이 사건 수사대 인물 칸 `.R`에 걸려 초록 상자가 생긴 적이 있어 `kz-R`로 바꿨습니다. 배경 구름 규칙 `.yard .c1`이 기차 칸 `.car.c1`에도 걸려 두 번째 칸이 기관차 앞으로 튀어나간 적이 있어 `.cl.c1`로 좁혔습니다. 장면 CSS는 `.장면 .역할.이름`처럼 구체적으로 쓰세요.
- 같은 이유로 v26에서 두 가지를 더 고쳤습니다: 영웅 화면의 레벨 보상 줄 `.track`이 글자 기차 선로 `.track`(절대 위치)에 걸려 카드 밖으로 튀어나감 → `lvtrack`. 동화책 안내 문구 `#bMsg`가 옛 배틀 화면의 `#bMsg`와 id가 같아 숨은 칸에 써지고 있었음 → `bkMsg`. id도 겹치지 않게 하세요 (`chaos-sim.js`가 같은 id를 찾아 줍니다).
- 음성 기다리기: `narrate()`는 새 음성이 시작되면 앞 음성의 완료 콜백을 부르지 않습니다. 그래서 "음성이 끝나면 다음 단계"로 짠 흐름은 도움말·🔊·다른 대사가 끼어들면 멈출 수 있습니다. 동화책은 `bSpeak()`(끼어들면 끝난 것으로 처리)를 쓰고, 사건 수사대는 `kzSay()`(최대 대기 시간)나 감시 타이머를 쓰세요. 화면이 사라진 뒤에 도는 `setTimeout`은 요소·상태가 아직 있는지 먼저 확인하세요 (예: `if(DU!==D0)return`).
- 화면 글자를 바꾸면 그 줄의 녹음 파일 연결이 끊깁니다(열쇠가 대사 글자). 바꾼 줄은 대본 CSV도 같이 고치고 다시 녹음하세요.
- 영어/한국어 문구는 `K(en, ko)` 또는 `UI.en / UI.ko`에 함께 있습니다.
